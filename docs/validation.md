PC와 Pixel 7은 `/usr/bin/chromium`을 사용한 **브라우저 에뮬레이션**이다. 실기기 테스트가 아니다. 데스크톱 프로젝트의 터치 전용 1개는 의도적으로 건너뛰고, 모바일 프로젝트에서는 실제 CDP touchStart/move/end를 보내 통과했다. 휠 검사는 별도다.

브라우저 시나리오는 대시보드·두 모드·미응답·답안 변경·북마크·새로고침·제출 확인 취소/확정·전체 해설·오답 복습·통계·JSON/CSV 등록·중복 제거·로컬 승인·초기화·백업 다운로드·손상 원본 보존·저장 실패 경고를 포함한다. 150분 타이머는 브라우저 가상 시계로 경과시켰고 실제 150분을 기다린 테스트는 아니다. 만료 재접속·타이머 콜백 전 만료 답안 클릭·중복 제출도 검사한다.

두 모드의 Space는 실제 keydown/keyup과 본문 포커스로 확인했다. 수정키·미응답·길게 누르기·네이티브 버튼·select·대화상자·마지막 문제 보호를 검사한다. 기준 앱의 60번 상한 잔재를 수정하고 **60→61번 이동과 100번의 다음 버튼 비활성**을 별도 검사한다. IME 조합·contenteditable 보호는 구현되어 있으나 한국어 IME 실사용 세션은 실행하지 않았다.

메뉴는 390×480, 740×360에서 실제 휠로 아래/위 이동하고 초기화 도구와 대시보드의 뷰포트 진입·선택을 확인한다. 모바일에서는 글자 확대 후 터치 스와이프로 내려 백업을 다운로드하고, 높이 420으로 변경한 후 위로 돌아와 대시보드를 선택했다. `scrollTop` 값을 강제 변경해서 통과시키지 않았다.

단위 테스트는 모든 1,000개 문항의 독립 재계산·정답 인덱스·단위·유일한 정답·해설 수치, 25 family별 40개 고유 입력, ID·정규화 중복 0, 수치 범위, 결정적 재생성, 과목별 20문항 추출과 검증 대기 제외, 합격 59/60점과 과락 35/40점 경계, 저장 복원·손상 과목 분포 거부, 중복 제출, 랜덤 순회와 가져오기 검증을 포함한다. 배포 workflow의 수동 전용 계약도 회귀 검사한다.

초기 npm 설치는 기본 캐시 경로(`/home/agent/.npm`)가 쓰기 허용 범위 밖이어서 실패했다. `/tmp` 캐시로 수정 후 checksum/TLS 검증을 유지한 `npm ci`가 성공했다. 설치 무결성 검증을 끄거나 lockfile의 체크섬을 바꾸지 않았다.
